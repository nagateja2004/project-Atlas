Problem / the fracture

The specification and the site stop agreeing — and nobody finds out until commissioning.

How a deviation is caught today
  • Specifications sit in PDFs on a shared drive
  • Vendor submittals arrive as email attachments
  • RFIs live in a spreadsheet, answered from memory
  • Primavera P6 runs in its own silo, updated weekly
  • Commissioning is executed on a clipboard
  • The connection between them is a senior engineer who remembers

The information exists. The intelligence that connects it never gets built — so a 50 kAIC shortfall in a submittal becomes an energisation date nobody re-planned.

Solution / what Atlas is

Atlas is the evidence layer between the documents and the decision.

It ingests the project's own specifications, submittals, RFIs, schedules and commissioning procedures, and keeps one connected, cited line from a requirement to the person who signs off on it.

01 · The spine
Equipment Digital Thread

For any tag — SWGR-A, UPS-A — the current specification, the vendor submittal, every compliance finding, the shipment, the schedule tasks, commissioning status, open NCRs and the evidence links, in one project-scoped view.

Implemented
02 · The propagation
Evidence-backed Impact Chain

A verified deviation propagates deterministically: specification → vendor resubmission → delivery risk → schedule impact → commissioning readiness → human decision. Each hop carries the document, page and span it came from.

Implemented
03 · The guardrail
The evidence gate

If the project's own documents don't support an answer, Atlas returns INSUFFICIENT_EVIDENCE instead of completing the gap from model knowledge. Refusal is a designed behaviour, not a failure mode.

Implemented

Instead of opening five tools and reconciling by hand, an engineer asks once — and gets the chain, with the page number.

Solution / how it works

The model explains. It never decides.

Request path
IngestPyMuPDF · OCR fallback · CSV

Pages, sections, contextual chunks, content hash, project-scoped Qdrant vectors.

Retrievedense + BM25 → RRF → rerank

Query rewrite, intent and metadata filters, project-filtered hybrid search, cross-encoder rerank, parent expansion. No LLM in the ranking.

Gatesufficient, or refuse

Evidence sufficiency check, then claim/citation verification on the way out.

Computedeterministic Python

Unit-normalised compliance comparison, CPM float and delay propagation, weighted readiness, mitigation arithmetic.

Decide & recordhuman action

Approve / reject / request review, persisted with the evidence it was taken on.

Cited, or silent
